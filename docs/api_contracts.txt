1. Canonical Error Model

Every error response from every endpoint uses this single shape. No endpoint deviates from it.

1.1 Universal Error Body
// Pydantic model
class ErrorResponse(BaseModel):
    error: str          # machine-readable error code, e.g. "indexing_in_progress"
    message: str        # human-readable explanation
    repo_id: str | None = None   # present when error is repo-scoped
    details: dict | None = None  # present for 422 field-level errors only

Stale .indexing marker rule (must be applied before every 409 check):
Before checking for a .indexing file, scan all ./repos/*/. indexing files.
For any whose mtime > 1800 seconds (30 min): delete the file.
Only then check for the remaining .indexing files.
An absent or freshly-deleted marker means no indexing is in progress for that repo.

Size check order (both checks are mandatory):
1. Reject immediately if uploaded content-length > 15 MB (compressed).
2. Open ZIP, sum ZipInfo.file_size for all entries. If total > 200 MB: reject 413.
3. Extract to ./tmp/{job_id}/. After extraction, recheck on-disk bytes <= 200 MB.
4. Move filtered files to ./repos/{repo_id}/.
Response is returned immediately (202). Indexing runs in background.

Guard order for /ask (must execute in this exact sequence):
1. Stale-marker cleanup: delete ./repos/{repo_id}/.indexing if mtime > 1800s.
2. 409 check: if ./repos/{repo_id}/.indexing exists, return 409.
3. 404 check: if ./repos/{repo_id}/repo_meta.json absent, return 404.
4. Proceed with retrieval.

Evidence labeling and LLM call ordering (CB-1 fix — non-negotiable):
Step 1: Finalize chunk list (post-dedup, post-diversity-cap, post-sort).
Step 2: Assign E1..Ek labels in final list order. E1 = index 0, Ek = last.
Step 3: Build LLM prompt embedding the labeled chunk texts.
Step 4: Call LLM. The LLM receives and must cite only the E-IDs from step 2.
Violation of this order produces evidence ID mismatch and breaks all citations.

Overview detection — canonical keyword list (SA-1 fix):
Case-insensitive substring match on stripped question string.
Keywords: overview | summarize | summary | explain the codebase | what does this repo |
          high level | high-level | architecture | walkthrough | overall structure
Any single match triggers overview mode. No model call. No extra latency.

Fallback A — LLM failure handling (CB-3 fix):
try:
    parsed = json.loads(llm_response_text)
    if not isinstance(parsed, list): raise ValueError('non-list')
    claims = parsed
except (json.JSONDecodeError, ValueError):
    claims = []
    llm_fallback_used = True
Backend NEVER raises 500 due to LLM output. chunks and confidence_score are always returned.

Confidence computation — mechanical only (CB-4 fix):
Requires hnsw:space=cosine on every Chroma collection.
sim_i = 1 - chroma_distance_i   (valid only with cosine distance)
confidence_score = round(mean([sim_1 ... sim_k]), 2)
confidence_label: >= 0.55 = High | >= 0.35 = Medium | < 0.35 = Low
Frontend must show warning banner when confidence_label == 'Low'.

Guard order for /impact (identical to /ask):
1. Stale-marker cleanup: delete ./repos/{repo_id}/.indexing if mtime > 1800s.
2. 409 check: if ./repos/{repo_id}/.indexing exists, return 409.
3. 404 check: if ./repos/{repo_id}/repo_meta.json absent, return 404.
4. Proceed with grep + vector pipeline.

Risk level computation — mechanical only:
file_count = len(files_referencing)  [referencing files; definition file excluded]
0 or 1 files -> Low | 2 or 3 files -> Medium | 4+ files -> High
LLM never sets, suggests, or influences risk_level. The LLM risk_level field (if
present in LLM output) is discarded. risk_level in the response always comes from
the grep file_count computation above.

Evidence merge and labeling order for /impact:
1. Build grep chunks (context-windowed, bounds-clamped: start=max(0,line-10), end=min(len,line+10)).
2. Embed function_name -> query Chroma top-6 (no diversity cap on /impact).
3. Merge. Deduplicate by (file_path, start_line, end_line). Keep first occurrence.
4. Order: grep evidence first, then vector evidence.
5. FREEZE list. Assign E1..En labels in order.
6. Build LLM prompt AFTER step 5. LLM call happens AFTER labeling.

3. Core Shared Models

3.1  EvidenceChunk
class EvidenceChunk(BaseModel):
    """
    Shared by AskResponse and ImpactResponse.
    Used for both vector and grep evidence chunks.
    """
    evidence_id: str
    # Format: 'E1', 'E2', ... 'Ek'
    # Assigned in final list order AFTER the chunk list is fully frozen.
    # LLM call occurs AFTER labels are assigned. Never before.

    file_path:   str
    # Path relative to repo root. No leading slash.
    # Example: 'src/auth/middleware.py'

    start_line:  int
    # 0-indexed line number of first line of chunk.

    end_line:    int
    # 0-indexed line number of last line of chunk (inclusive).

    text:        str
    # Raw text content of the chunk (or grep context window).

    similarity:  float | None
    # For source='vector': round(1 - chroma_cosine_distance, 4). Range [0.0, 1.0].
    # For source='grep':   MUST be null. Never 0. Never omitted.

    source:      Literal["vector", "grep"]
    # 'vector' = retrieved from ChromaDB embedding search.
    # 'grep'   = retrieved via word-boundary regex match on source files.

3.2  AskResponse
class Claim(BaseModel):
    claim:    str        # LLM-generated claim string
    evidence: List[str]  # Subset of ['E1'..'Ek'] from frozen chunk list
    # All evidence IDs must exist in the accompanying chunks array.
    # LLM is constrained to cite only E-IDs it was given in the prompt.

class AskResponse(BaseModel):
    repo_id:           str
    retrieval_mode:    Literal["standard", "overview"]
    # 'standard': 8 chunks returned, soft diversity cap 4/file.
    # 'overview': 20 chunks returned, hard diversity cap 2/file.

    confidence_score:  float
    # round(mean([1-d for each selected chunk distance]), 2)
    # Requires hnsw:space=cosine. Range: [0.0, 1.0].

    confidence_label:  Literal["High", "Medium", "Low"]
    # High: confidence_score >= 0.55
    # Medium: 0.35 <= confidence_score < 0.55
    # Low: confidence_score < 0.35  [frontend shows warning banner]

    claims:            List[Claim]
    # Empty list ([]) when llm_fallback_used == True.
    # Non-empty only when LLM returned valid JSON list.

    chunks:            List[EvidenceChunk]
    # Final frozen list. Length: 1..8 (standard) or 1..20 (overview).
    # E-IDs in this list are the only valid citation targets for claims.

    llm_fallback_used: bool
    # True if: LLM call failed, JSON parse failed, or parsed result was not a list.
    # When True: claims=[], chunks and confidence still populated normally.

3.3  ImpactResponse
class ImpactResponse(BaseModel):
    repo_id:           str
    function_name:     str

    risk_level:        Literal["Low", "Medium", "High"]
    # MECHANICAL ONLY. Derived from file_count (referencing files only).
    # 0-1 -> Low | 2-3 -> Medium | 4+ -> High
    # LLM output is never used to set this field.

    file_count:        int
    # Count of files_referencing. Does NOT include the definition file.

    files_referencing: List[str]
    # Relative paths of files containing a word-boundary grep match,
    # excluding the definition file (if detected).

    what_it_does:      str
    # LLM summary of the function based on evidence chunks only.
    # Empty string ('') when llm_fallback_used == True.

    message:           str | None
    # Non-null only when grep finds zero matching files.
    # Value: "No exact word-boundary grep matches found. Showing semantic evidence only."
    # null in all other cases.

    chunks:            List[EvidenceChunk]
    # Grep chunks first (similarity=null), then vector chunks.
    # Max 2 grep context windows per referencing file.
    # Up to 6 vector chunks (no diversity cap on /impact).
    # Deduplicated by (file_path, start_line, end_line).
    # E1..En assigned AFTER list is frozen. LLM call after labeling.

    llm_fallback_used: bool
    # Same Fallback A semantics as AskResponse.
    # When True: what_it_does='', chunks still populated normally.

4. Inviolable Rules Quick-Reference

The following rules may not be altered, relaxed, or reinterpreted during implementation.

Rule
Specification
Chroma distance
hnsw:space=cosine on EVERY get_or_create_collection() call. This is a pre-condition for sim=1-d to be valid.
sim formula
sim = 1 - chroma_cosine_distance. Result is in [0.0, 1.0].
Confidence
mean(sims of selected chunks), rounded to 2 decimals. Labels: >=0.55 High, >=0.35 Medium, <0.35 Low.
Risk
file_count of files_referencing only. 0-1=Low, 2-3=Medium, 4+=High. LLM never influences this.
Evidence labeling
Freeze list -> assign E-labels -> build LLM prompt. This order is mandatory.
Fallback A
json.loads() + isinstance(result, list) check. Either failure -> claims=[], llm_fallback_used=True. Never 500.
similarity on grep
null. Never 0. Never omitted.
Stale marker
mtime > 1800s -> delete before every 409 check.
Repo oracle
repo_meta.json presence = repo exists. Absence = 404.
mode field
Accepted in request, never read. Backend always auto-detects.
/health & /status
Never return 409. Never blocked by indexing state.
Collection name
f'repo_{repo_id}' always. seed_demo_repo.py uses repo_demo_repo.
